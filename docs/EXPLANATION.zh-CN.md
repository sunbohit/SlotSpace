## 0. 先说结论

- **SlotSpace 是什么**：用一份 Schema 定义的“槽位空间”，把 Query 理解、文档建索引、歧义词典和检索规划绑在一起。文档按“事实（fact）”存储；打分时要求**值、角色、上下文出自同一条事实**（绑定），歧义的读法在**一次检索**里一起执行。
- **为什么能同时提升 Coverage 和 Efficiency**：
  - Coverage：读法用保形方法（conformal）保留，有统计保证；软融合不硬过滤；BM25 和稠密检索始终作为兜底。
  - Efficiency：候选生成与读法无关，一次检索服务所有读法；零支持读法在执行前删掉且**可证明不丢分**；贵的绑定打分只在有限候选上算。
- **v0 范围**：只做 STaRK-Prime，纯 Python/numpy 研究路径，全部开源模型（查询时模型 < 1B），一张 24 GB GPU。Vespa 引擎版放到 v1。
- **诚实定位**：单个组件都有前人工作（PRMS、mFAR、COIL、ColBERT、IA-Select、保形预测等），新意在于**围绕同一槽位空间的组合**（D1.5 的 N1–N4），价值由实验决定。
- **写文档时已经实测过的内容**：参考实现 + 12 个单测全部通过；快速打分器与参考实现一致（float 和 binary 两种）；合成实验数字；链接/遮蔽/分句代码；统计函数；MDE 表。外部事实（STaRK API 与数量、Vespa 语法要点、模型许可证）都对照了官方代码或文档。

## 1. 全流程一张图

```
文档侧（离线）
  KB 实体 ──► 原生事实（KB 边，角色确定，π=1）──────────────┐
         └─► 文本事实（句子）：字典链接值 → 遮蔽 → 槽位打分器 π │
                              └─► 上下文向量 c_f（128 维）    ├─► 索引 + 歧义词典 L/H（索引的视图，增量维护）
                                                               ┘
查询侧（在线）
  Query ─► 链接（值 + 链接概率 ℓ）─► 遮蔽值 ─► 槽位打分器 C（含 none）
        ─► 后验 p ∝ ℓ · C · E^β（E 来自词典；H=0 的读法直接删）
        ─► 保形阈值保留读法（概率 ≥ t_α，至少保留 1 个）
        ─► 一次检索：BM25 top-200 ∪ 稠密 top-200 ∪ 读法键的倒排
        ─► 绑定打分 B(d) ─► 与稠密、BM25 软融合 ─► Top 100 + 证据（命中的那条事实）
```

## 2. 要解决的问题（对应 D1–D2）

### 2.1 三个“高血压”查询

| 查询 | 值 | 角色 | 正确答案 |
|---|---|---|---|
| 哪些药治疗高血压？ | 高血压（疾病） | 适应症 indication | 一批药 |
| 高血压患者应避免哪些药？ | 高血压（疾病） | 禁忌 contraindication | 另一批药 |
| 哪些药会引起高血压？ | 高血压（**表型**） | 副作用 side effect | 又一批药 |

值相同，答案几乎不重叠，差别全在**角色**。单向量稠密检索把整篇文档压成一个向量，分不清“禁忌高血压”和“治疗高血压”；BM25 只看词。

### 2.2 三种歧义

1. **链接歧义**：“hypertension” 是疾病节点还是表型节点？
2. **槽位歧义**：值确定后，它在哪个槽位（适应症 / 禁忌 / 超说明书用药）？
3. **Schema 碰撞**：同一个值在**这个语料**里确实出现在多个槽位。碰撞是**语料属性**，不是 Query 属性——没有碰撞，语料本身就能消歧。

### 2.3 绑定问题（为什么要“同一条事实”）

一篇药物文档有两句话：f1 “哮喘患者禁用”，f2 “试验中报告过高血压”。对“高血压患者应避免哪些药”，这篇文档**不该**高分。但如果分开取最大值（值从 f2 来、“禁用”语境从 f1 来），就会把两条事实的证据拼在一起——这就是**绑定问题**。SlotSpace 要求值、角色概率、上下文相似度在**同一条事实**上同时成立，再对事实取最大值。

### 2.4 为什么只看 Query 判断不了槽位

把槽位 k 的合理性拆成两个因子：

- **C(k|q)，语境兼容**：Query 里这个提及周围的词像不像槽位 k？只依赖 Query 和 Schema，**模型可以学**。
- **E(k|v)，语料证据**：值 v 在这个语料里有没有以槽位 k 出现、出现多少？依赖语料、随文档变化，**只看 Query 的模型不可能知道**。

所以：模型**只学 C**（输入里把值遮蔽掉，防止它记住“高血压通常是适应症”这种语料先验），E 在查询时从歧义词典读取。

### 2.5 扇出改写的代价

“每个读法改写一个 Query 分别检索再合并”：m 个提及、各 R_i 个读法时，组合枚举要 ∏R_i 次检索；即使每个读法一次，也要 ΣR_i 次完整检索（各自的 BM25、向量检索、重排）。SlotSpace 只做一次检索，读法只改变第二阶段打分的权重。

## 3. 核心设计逐条讲解（对应 D5–D10）

### 3.1 Schema = 场景超参数（D5）

- 一个领域一份 YAML。槽位 id 格式 `<文档类型>.<关系>.<值类型>`，例如 `drug.contraindication.disease`，**永远从文档的角度写**。
- 每个槽位有一两句自然语言描述（给打分器和数据生成器用），以及只给训练模板用的提示短语（cues）。
- **Schema 闭集、版本化；值开集、来自语料**。改描述或加槽位很便宜：重新生成训练数据、微调（或用描述零样本打分）、重打文本事实、重建词典；**文档不用重新向量化**。
- Prime 的事实（已核对 STaRK 代码）：10 种节点类型、18 种关系（名字里有空格和连字符，如 `off-label use`），**129,375 个节点全部是候选**；每条边**双向存储**（8,100,498 = 2 × 4,050,249），所以药物文档和疾病文档各自自然得到 `drug.indication.disease|n…` 和 `disease.indication.drug|n…`；同类型之间的关系（`parent-child`、`ppi`）方向不可恢复，按对称处理。
- 槽位清单**从数据里统计导出**（按 源类型×关系×目标类型 计数），不手写；描述再人工写。

### 3.2 事实（D6）

| | 原生事实（native） | 文本事实（text） |
|---|---|---|
| 来源 | 一条 KB 边 | 一个句子（只保留含已链接值的句子） |
| 键 | `slot|value`，π = 1 | 每个值一个分布 π（只存 ≥ 0.05 的格子） |
| 上下文 | 不需要向量（上下文因子取常数 1） | 128 维向量 c_f（所有值遮蔽为类型，带字段名前缀） |
| 存储 | 文档的 `native_keys` 集合 | 事实列表 + 向量矩阵 |

要点：

- 打分器输入：目标提及 → `[TARGET:类型]`，其他提及 → `[类型]`，文档自身名字 → `[SELF:类型]`；**不带字段名**（合成训练数据无法还原字段与槽位的真实关联）；字段名只进上下文向量文本。
- **必须有 `none` 选项**：否则某个值类型只有一个候选槽位时（例如药物文档里的表型只能是“副作用”），π 永远是 1，词典会被污染。
- 文档侧同一类型同名多节点的提及直接跳过（统计并报告），保持词典干净。
- 链接规则（偏重精确率）：最长匹配、不重叠；名字少于 3 个字符、纯数字、常见英文单词（单词形式）不链接；全大写基因符号（如 CAT）要求大小写完全一致。

### 3.3 绑定打分公式（D7.1）

对读法 r = (提及 s, 槽位 k, 值 v)：

- **门控**：γ_f(r) = ℓ_r · π_f(k|v)（π < 0.05 时为 0）——这条事实是否以这个槽位持有这个值、有多确定。
- **原生部分**：N_r(d) = ℓ_r^a · 1[k|v 在 native_keys(d) 中]。
- **文本部分（绑定）**：T_r(d) = max_f γ_f(r)^a · ψ(⟨g_s, c_f⟩)^b，ψ(x)=max(0,x)。**所有因子来自同一条 f**，最好的事实胜出。
- **读法匹配** M_r(d) = max(N_r, T_r)；**绑定分** B(d) = Σ_r w_r · M_r(d)。
- **最终分**：S(d) = λ_B · B(d)/max(m,1) + λ_D · 稠密(归一化) + λ_L · BM25(归一化)；m 为有读法的提及数。没有读法时就退化为混合检索基线。

几个“为什么”：

- **为什么取 max**：一条支持事实就够（与 MaxP、MaxSim 同理，“存在性”语义）。
- **为什么用乘积**：任何一个因子为 0（值不对、角色概率太低、语境相反），这条事实就不算数。
- **为什么原生事实的上下文因子取常数 1**：原生事实的槽位是确定的，而 w_r 里已经包含了 C(k)，再拿 g_s 和槽位描述向量比一次就是重复计票。取常数后，w_r · N_r 的含义很干净：“用户想要 r 的概率” × “文档确定满足 r”。
- **解释**：如果 w_r 是读法概率、M_r 是文档满足读法的概率，B(d) 就是**文档满足的查询约束个数的期望**——这是读法不确定时的概率排序原则，所以默认 w = p。

### 3.4 五个性质（D7.4，都有证明和单测）

| 性质 | 通俗含义 |
|---|---|
| P1 绑定 | 文本部分 > 0 当且仅当**同一条**事实同时满足值、角色、正向语境；分开取最大值的做法没有这个保证 |
| P2 零支持剪枝无损 | 词典硬支持 H=0 的读法，对所有文档得分都是 0，删掉不改变任何文档的分数（前提：词典不比索引旧，H 不少计） |
| P3 一次检索 vs 扇出 | 组合枚举的倒排工作量是单次的 1 到 ∏R_i 倍；按读法改写则把整套检索重复 ΣR_i 次 |
| P4 有界 | 0 ≤ M_r ≤ 1，0 ≤ B ≤ m |
| P5 单调 | 角色概率、链接概率、语境相似度变大或文档多一条事实，分数都不会下降 |

### 3.5 玩具例子怎么读（D7.5，数字由参考实现算出）

“高血压患者应避免哪些药？”——后验：禁忌 **0.6254**、适应症 **0.2014**、副作用（表型）**0.1732**；超说明书用药因硬支持为 0 被删除。

| 文档 | 绑定（SlotSpace） | 分开取最大 | 只看门控 | 不看角色 |
|---|---|---|---|---|
| A（适应症为高血压） | 0.2032 | 0.2032 | 0.2327 | **0.8268** |
| B（相关：禁用于高血压） | **0.4237** | 0.4237 | 0.4256 | 0.8232 |
| C（陷阱：禁用于哮喘；中性提到高血压；有高血压副作用边） | 0.3148 | **0.4302** | **0.4313** | 0.6269 |
| D（无关） | 0 | 0 | 0 | 0 |
| 排序 | **B, C, A, D** | C, B, A, D | C, B, A, D | A, B, C, D |

- “分开取最大”把 C 排第一：值来自 f2、“禁用”语境来自 f1——典型的跨事实拼接。
- “只看门控”也把 C 排第一：副作用原生边打开了门控，却没人检查语境对不对。
- “不看角色”把 A 排第一：适应症证据被当成了禁忌证据。
- 只有绑定版本把相关文档 B 排第一。

### 3.6 合成实验的诚实解读（D7.6）

2,000 篇文档、300 个查询、种子 7：

| 设定 | 绑定 | 分开取最大 | 只看门控 | 不看角色 |
|---|---|---|---|---|
| 默认（文档侧角色准确率 52.6%） | 0.835 | 0.483 | 0.436 | **0.880** |
| 文档侧角色模型更准（80.3%） | **0.888** | 0.635 | 0.601 | 0.880 |
| 上下文向量更弱 | **0.573** | 0.447 | 0.436 | 0.536 |

（指标为 R-precision）结论：**绑定在所有设定下都明显好于“分开取最大”和“只看门控”**；但“角色分布 π”是否在上下文向量之外还有增益，取决于两者谁更可靠——文档侧角色模型弱时，只用上下文反而略好。所以 A1（不看角色）是一个真实的问题，指数 a、b 需要调。这也是为什么文档强调“仿真只证明代码按预期工作，不是真实数据上的证据”。

### 3.7 歧义词典（D8）

- 定义：文档贡献 c_d(v,k) = 文档内各事实 π 的最大值（原生 = 1）。**软支持** L_v[k] = Σ_d c_d；**硬支持** H_v[k] = c_d ≥ 0.05 的文档数。先文档内取 max、再跨文档求和，因为规划器要的是“有多少文档能满足这个读法”。
- 用途：后验里的 E、无损剪枝、成本估计（H 就是倒排长度）、碰撞诊断、生成角色互换测试集。
- 分层（回答你之前的问题——**是随文档动态构建的开集**）：

| 层 | 内容 | 开/闭 | 谁改 |
|---|---|---|---|
| L0 | Schema 与约定 | 闭，版本化 | 人 |
| L1 | 每个值类型的通用先验（v0 用均匀） | 闭 | 配置 |
| L2 | 值及其计数 L、H | **开**，随语料增长 | 写入时，提交即可见 |
| L3 | 证据指针（每个 (v,k) 最多 5 个事实 id） | **开** | 写入时 |
| L4 | 挖掘的别名 | 开但有门槛（精度检查后才加） | v1 |

- 增量维护：每篇文档存一份贡献记录；更新 = 减旧加新；删除 = 减旧；索引和词典一起提交。
- 四个不变量：I1 求和一致；I2 查询看到的词典版本不旧于索引；I3 H **只允许多计不允许少计**（延迟删除可以，提前删除不行），保证剪枝无损；I4 从零重建 = 增量结果。
- **PACC 校正**：文本事实来的软计数会继承打分器的偏差。用“远程监督集”（文档文本里提到的值，恰好 KB 里有对应的边，边的槽位就是真值）测每个槽位的 TPR、FPR，然后 校正比例 = (平均后验 − FPR)/(TPR − FPR)。例：均值 0.40、TPR 0.80、FPR 0.15、200 篇 → 76.9（原始和为 80）。剪枝仍用原始 H（剪枝要的是“无损”，不是“准确”）。

### 3.8 查询侧与后验（D9）

- **候选槽位**：提及所有可能值类型的槽位（任何文档类型）+ `none`。这样语境可以同时决定答案类型（“Which **drugs**…”）和同名多类型时的值类型。
- **打分器**：v0 用交叉编码器给（遮蔽语境，槽位文本）打分，再按温度做 softmax；底座 ModernBERT-base（1.49 亿参数，Apache-2.0）；零样本对照用 bge-reranker-v2-m3（Apache-2.0，多语言）。查询、文档两种风格共用一个模型，各自一个温度。
- **后验推导**（Saerens 先验迁移）：训练数据各槽位均衡（均匀先验）时，C(k|x) ∝ P(x|k)，只衡量语境匹配；再乘新先验 E(k|v)^β：

  p_r ∝ ℓ(v|类型) · C(k|x) · E(k|v)^β，E 做加一平滑；H=0 的读法直接删除。

- **β 的含义**：β=1 表示用户意图服从语料分布；β=0 完全不看语料；默认 0.5 是折中——角色互换查询一半在问“少见的那个槽位”，β=1 会把它压没。β 用 plan regret 在验证集上调。
- **none 的作用**：整个提及是不是约束的概率 = 1 − C(none)，作为这个提及的总权重。

### 3.9 规划器（D10）

1. **读法集合**：零支持剪枝 → 保形阈值（校准集上取“真读法概率”的分位数）→ 至少保留 1 个、最多 6 个 → 归一化到 1 − C(none)。保证：在可交换假设下，最佳真读法被保留的概率 ≥ 1 − α（默认 α=0.1）。例：19 个校准值、α=0.1 时阈值 t=0.35，玩具查询只保留“禁忌”读法。
2. **权重目标**：`p`（期望满足约束数，默认）、`p_over_H`（照顾支持少的读法，偏召回）、`ia`（IA-Select 重排，偏覆盖：让每种可能意图都有好结果靠前）。
3. **执行路径与兜底**：没有读法 → 只走 BM25 + 稠密；有读法 → BM25 ∪ 稠密 ∪ 读法键倒排（倒排超过 500 时按稠密分截断）。**BM25 与稠密候选永远在池子里**，这是链接或槽位判断出错时的覆盖兜底。
4. **硬 AND vs 软融合**：硬 AND 便宜但一错就丢相关文档，只作为消融 A6。
5. **成本计数器**：BM25 倒排量、稠密检索次数、值倒排量（=Σ H）、候选数、算过的事实数、查询时编码文本数、各阶段延迟。每个质量数字旁边都要有这些。
6. **Plan regret（模型与超参的选择指标）**：同一流程下“用银标签真读法的 oracle 计划”与“实际计划”的倒数排名之差。为什么不用槽位准确率：不改变排序的错误不值钱，把相关文档挤出前 10 的错误很贵。

## 4. 小模型：按 Schema 生成数据并微调（D11、M5）

### 4.1 和你的思路逐条对应

| 你的思路 | 文档中的落地方式 |
|---|---|
| “片段–slot 打分器” + 精确证据 | 槽位打分器给语境兼容 C / 文档侧 π；精确证据来自字典链接的值 id 和词典计数 |
| 小于 1B 的模型微调 | ModernBERT-base 交叉编码器（1.49 亿参数） |
| Schema 预先定义，作为场景超参数 | `schemas/prime.yaml`，闭集、版本化；值是开集 |
| 小模型基于 Schema 动态 Generate & Finetune | 模板 → 代号词 → 本地 LLM 改写 → 规则校验 → 遮蔽 → 均衡 → 微调 |
| 小模型影响 Query planning | 模型输出 C 与 none 进入后验和读法集合；用 plan regret 选模型 |
| 在开源评测集上测 | STaRK-Prime（官方查询）+ 基于 KB 的角色互换集 |

v0 和之前讨论的一个具体差异：**v0 没用 GLiNER2**。原因是 Prime 的值是 KB 节点（闭合词表），字典链接 + 交叉编码器更简单、更稳、更好调试；GLiNER2（205M，Apache-2.0）留到 v1 处理开放词表的值（Amazon 属性、MAG 主题）。接口（`score(语境, 候选槽位, 温度)`）保持不变，实现可替换。

### 4.2 学什么、不学什么

- 学：P(槽位 | 遮蔽后的语境, 值类型)。
- 不学：具体值的先验。输入里永远看不到值字符串（目标 → `[TARGET:类型]`）。
- 检验：消融 A12 用“值可见”训练同一个模型，在角色互换集上对比（那里各槽位的意图是均衡的，与语料频率不同）。

### 4.3 数据生成流程

1. **模板**：每个槽位 ≥ 12 条查询风格 + ≥ 12 条文档风格；每个值类型一组 `none` 模板（提到值但不表达任何关系）。
2. **代号词**：占位符填入唯一的伪词（如 `Zorvex17`），这样改写模型会原样保留，事后能精确找回并替换成遮蔽标记。
3. **改写**：本地 `Qwen3-4B-Instruct-2507`（Apache-2.0，无思考模式）用 vLLM 离线批量，每条 3 个改写。
4. **规则校验（不用 LLM 打分）**：伪词缺失或重复、长度不在 4–60 词、含有碰撞槽位的提示短语、重复 → 拒绝。
5. **困难负例**：碰撞槽位之间做最小对（只换提示短语）。
6. **多提及**：30% 样本含第二个不同角色的提及，逼模型读“挂在目标上的”提示词。
7. **无类型目标**：20% 样本写成 `[TARGET]`，应对同名多类型。
8. **均衡**：每个值类型内各槽位（含 none）样本数相同——这是后验公式成立的前提。
9. **留出槽位**：再训练一个不含“超说明书用药”的模型（A14），测 Schema 描述的零样本迁移。

### 4.4 训练、校准与银标签

- 训练：交叉编码器，（遮蔽语境，槽位文本）配对，正例 1、同值类型的其他候选（含 none）为负例 0；BCE 损失，`pos_weight` = 每个正例对应的负例数；2 个 epoch，学习率 2e-5，按模板 id 留 10% 做开发集，保留最佳检查点。
- 校准：分别为查询风格和文档风格拟合温度（最小化 NLL），报告校准前后 ECE（15 个箱）。
- **银标签（不用任何 LLM）**：对 STaRK train/val 查询，看答案实体的 KB 边——如果至少一半答案都有边 `k|v`，那 k 就是这个提及的真槽位。用于温度、保形阈值、plan regret；**绝不在 test 上计算**。人工抽查 100 条，一致率低于 80% 就停下来讨论。

### 4.5 防止“自己出题自己考”

- 角色互换**测试模板单独成文件**，只有构建脚本能读；训练和改写永远不碰（开发文档要求加一个检查代码库的测试）。
- 改写模型的任何输出都不进测试集。
- 主结论放在 STaRK 自己的查询上（不是我们的生成器写的）。
- 报告留出槽位模型的结果。

## 5. 与现有工作的关系（D2.8）

| 工作 | 关系 |
|---|---|
| PRMS（ECIR 2009） | 最接近的祖先：从集合统计估计“词 → 字段”的概率。E(k|v) 是它在“值 → 角色”上的类比，加上文档内取 max 计数和学习到的 C |
| mFAR（ICLR 2025） | 最强的“按字段”基线：每字段词法 + 稠密打分、Query 条件化的字段权重。权重按 Query 而非按提及的读法，字段内部没有绑定 |
| COIL（NAACL 2021）/ CITADEL（ACL 2023） | 门控思想同源：只在相同 token / 路由键之间交互。SlotSpace 的键是 Schema 定义的显式类型化路由 |
| ColBERT / MaxP | 多向量、取最大；事实层就是多向量表示 |
| MUVERA（NeurIPS 2024） | v1 才考虑：把多向量压成单向量做一次 ANN |
| IA-Select（WSDM 2009） | `ia` 权重目标，读法当作意图类别 |
| Sarkas 等（SIGMOD 2010） | Query 侧结构化标注，含“都不是”的结果；SlotSpace 多了语料级计数和检索时的事实绑定 |
| Saerens 2002 / Guo 2017 / 保形预测 / PACC | 分别对应后验推导、温度校准、读法集合、词典计数校正 |

**结论**：不要声称任何单个组件是新的；可以主张的是 D1.5 的 N1–N4 组合，以及实验测得的效果。

### 6.1 数据（已核对）

| 集合 | 规模 | 用途 |
|---|---|---|
| Prime 知识库 | 129,375 个实体全部是候选；8,100,498 条存储边 | 语料 |
| train | 6,162 | 只做银标签 |
| val | 2,241 | 调参、选模型 |
| test | 2,801 | 主结果 |
| test-0.1 | 280 | 快速检查（论文的 LLM 重排只跑了这个子集） |
| 人工撰写集 | 98 | 只看方向（网站上的 109 已过时） |
| 角色互换 dev/test（自建） | 目标 test ≥ 1,000 | 绑定与槽位判断（H1、H2、H4） |

注意：STaRK 发布的查询**没有任何元数据**（为防止答案泄露被删掉了），所以关系信息只能从 KB 边推出来——这也是银标签方案的依据。

### 6.2 角色互换测试集怎么造

1. 找碰撞值：疾病节点在“适应症 / 禁忌 / 超说明书”中至少两个槽位的原生支持在 3–100 之间。
2. 找跨类型碰撞：同名的疾病节点（适应症合格）和表型节点（副作用合格）。
3. 每个（值，合格槽位）用**测试专用模板**生成一条查询（模板按哈希确定），答案 = 所有带原生键 `k|v` 的文档。
4. 记录互换伙伴（同值或同名的其他槽位查询）及其答案。
5. 按值哈希分 dev/test，同一个值的所有查询在同一边。
6. test 少于 600 条就把下限从 3 降到 2，并记录。
7. 人工读 50 条看是否自然。

新增指标 **Role-Confusion@10**：前 10 里属于“伙伴查询答案但不属于本查询答案”的比例，越低越好。

### 6.3 基线与引用数字

- 重跑（同一嵌入模型、同一 BM25）：B0 BM25、B1 稠密、B2 混合、B3 句子级多向量（MaxP 式）、B4 字段加权（简化版 mFAR）、B5 不绑定版、B6 扇出（同一计划、每个读法一次改写、加权 RRF 合并）、B7 oracle 读法（仅 val）。

## 8. 风险与局限（D14）

- STaRK 合成查询由 LLM 写成，有风格偏差 → 同时报告人工集和基于 KB 的角色互换集。
- 银标签有噪声 → 只用于校准和选择，不作为测试真值；人工抽查。
- KB 不完整 → 文本事实 + BM25/稠密兜底；角色互换集答案的缺失对所有系统一样。
- 链接错误（基因符号、常见词）→ 精确率优先的规则 + 人工抽查。
- 基线可能已从文本中学到角色 → 这本身是合理结果；H1 看角色互换集，H5 看全量 test。
- 数据许可：STaRK 数据 CC-BY-4.0（代码 MIT）→ 发布时署名，只发代码、模板、查询 id 和构建脚本，不转存原始数据。
- 局限：值必须可链接（v0 用 KB 字典）；不处理时间歧义；C 与 E 的组合形式是固定的；保形保证是边际的，不是逐条查询的。
